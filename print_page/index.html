    FSL Learn — Filipino Sign Language Vocabulary Learning Platform¶

    Welcome to the FSL Learn System User Manual. FSL Learn (also branded as FSLearn) is an interactive, web-based educational platform designed to teach Filipino Sign Language (FSL) vocabulary. Built specifically for elementary and Special Education (SPED) environments, such as Tomas Sagun Integrated School, the platform bridges communication barriers for Deaf and hard-of-hearing learners, teachers, and hearing peers.

    The system addresses the severe shortage of localized, accessible, and structured digital tools for learning Filipino Sign Language. By combining visual sign demonstrations, interactive vocabulary learning, graded practice, multiple-choice quizzes, and computer-vision-assisted hand sign recognition, FSL Learn offers an engaging and supportive learning environment for Filipino classrooms.

    Note

    System Version: 2.0.0
    Manual Release Date: November 2026
    Architecture: PHP 8.x (Apache / PDO) backend with a FastAPI Python 3 Machine Learning service.

    Who This Manual Is For¶

    This user manual is designed for the three primary user roles operating the platform:

    • Students (Learners): Young learners and SPED pupils who browse sign lessons across three progressive levels (Alphabet, Basic, and Intermediate), watch animated sign demonstrations, complete lessons, and take interactive mastery quizzes.
    • Teachers: Educators who establish virtual classrooms, enroll and monitor student progress, oversee quiz performance and accuracy metrics, and conduct live classroom demonstrations using AI hand recognition.
    • Principal (Administrator): School administrators who oversee institutional performance, generate and manage cryptographically secure Teacher Registration Codes, and generate official school-wide progress reports.

    Key System Features¶

    FSL Learn provides comprehensive educational and administrative capabilities:

    • Structured Three-Tier Curriculum:
    • Alphabet: 26 letters of the FSL alphabet with letter cards and hand demonstration animations.
    • Basic Vocabulary: 15 thematic categories covering Numbers, Colors, Fruits, Vegetables, Family, Shapes, Animals, Body Parts, Food and Drinks, School Objects, School Subjects, Time, Weather, Everyday Greetings, and H-Questions.
    • Intermediate Vocabulary: 9 advanced categories covering Occupations, Transportation, Hobbies, Daily Routine, Emergencies, Community, Emotions and Opinions, Meet & Greet, and Money Matters.
    • Interactive Demonstrations and Tips: High-quality animated demonstration GIFs paired with Filipino and English translations, category badges, and actionable signing tips.
    • Multiple-Choice Quizzes: Automated assessments with immediate visual feedback trays, passing score evaluations (70% benchmark), and permanent database scoring.
    • Classroom Management & Unique Join Codes: Teachers create isolated classroom sections, generate 6-character alphanumeric join codes (e.g., QPELNG), and maintain a one-classroom-per-student enrollment policy.
    • Live Alphabet Hand Recognition ("Sign & Spell"): Real-time camera feed analysis using Google MediaPipe Hands (21 3D landmarks) and a Scikit-learn Random Forest model to verify hand signs live in the browser.
    • Administrative Code Generator: Two-factor re-authenticated code generation allowing the Principal to produce 16-character registration codes (FSL-XXXXXXXX-XXXXXXXX) with configurable expiration windows.
    • School-Wide Analytics and Exportable Reporting: Consolidated performance reporting filterable by School Year [TODO: confirm], Grade Level, and Section, with one-click export to PDF and CSV formats.

    System Installation and Setup Guide¶

    This guide provides technical instructions for configuring, deploying, and verifying the FSL Learn application on a local server or development workstation.

    The platform employs a hybrid architecture:

    • PHP Web Backend & Assets: Served via Apache (recommended: Laragon on Windows or XAMPP on macOS) using PDO MySQL.

    • Python Machine Learning Service: A FastAPI microservice running on Uvicorn that evaluates MediaPipe hand landmark vectors for real-time sign classification.

    System Requirements¶

    Before beginning the installation, verify that the host machine satisfies the following hardware and software requirements:

    | Component | Minimum Specification | Recommended Specification |

    | :--- | :--- | :--- |

    | Operating System | Windows 10 (64-bit) or macOS 12+ | Windows 11 (64-bit) or macOS Sonoma |

    | Web Server | Apache 2.4.x (via Laragon 6.x or XAMPP 8.2+) | Laragon 6.0 Full (Windows) |

    | PHP Runtime | PHP 8.1.x or 8.2.x (with PDO MySQL, JSON, cURL, OpenSSL) | PHP 8.2+ 64-bit |

    | Python Runtime | Python 3.10.x to 3.12.x (64-bit) | Python 3.11.9 (64-bit) |

    | Database Server | MySQL 8.0+ or MariaDB 10.4+ (Default port: 3306) | MySQL 8.0.35+ (utf8mb4 encoding) |

    | Client Browser | Google Chrome 110+, Microsoft Edge 110+, or Firefox 115+ | Google Chrome (optimal WebRTC and MediaPipe support) |

    | Camera Hardware | Integrated 720p webcam or USB web camera | 1080p 30fps webcam for live sign recognition |

    Warning

    Always ensure database credentials, secret keys, and passwords remain private. Never commit plain-text credentials to public repositories. Back up your fsl_learn database regularly before applying migrations or upgrading software packages.

    Step-by-Step Installation Instructions¶

    Follow these numbered steps to configure the web server, database, and Python services.

    1. Retrieve the Application Codebase¶

    Clone the project repository to your local workspace using Git [TODO: confirm repository URL], or extract the provided capstone release archive:

    git clone https://github.com/your_organization/FINAL-FSL.git

cd FINAL-FSL

    2. Configure the Web Server (Laragon on Windows)¶

    The easiest deployment environment on Windows is Laragon:

    1. Install and launch Laragon.

    2. Click Start All to activate both Apache and MySQL.

    3. Confirm that Apache is listening on port 80 (or 8080) and MySQL is listening on port 3306.

    4. Deploy the application files into Laragon's document root directory (C:\laragon\www\fsl_learn):

      • Create the directory C:\laragon\www\fsl_learn if it does not exist.

      • Copy all files from backend/php/ directly into C:\laragon\www\fsl_learn\.

      • Ensure .htaccess is copied to C:\laragon\www\fsl_learn\.htaccess to enable API URL rewrites.

      • Copy the frontend/ directory into C:\laragon\www\fsl_learn\frontend\.

    Alternatively, if running the Windows deployment helper script, execute start.bat in the project root:

    start.bat

    This automated batch script synchronizes the web assets, verifies the directory structures, opens the default browser, and launches the Python service.

    3. Set Up and Initialize the MySQL Database¶

    The application connects to a MySQL database named fsl_learn.

    You can import the schema manually via the MySQL CLI or HeidiSQL (included with Laragon):

    CREATE DATABASE IF NOT EXISTS `fsl_learn` CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

USE `fsl_learn`;

SOURCE C:/Users/dexte/Documents/GitHub/FINAL-FSL/database/fslearn_database.sql;

    Alternatively, the PHP backend contains an automatic bootstrap engine in backend/php/config.php. Upon the first API request, the system calls ensure_database() to automatically create missing tables, indexes, constraints, seed the 263 lessons, and restore the protected Principal account (username: principal).

    4. Configure Database and Environment Settings¶

    Database credentials and service URLs are defined in backend/php/config.php. By default, the system uses standard Laragon local credentials. You can override these using system environment variables or by editing your local configuration:

    # Database Connection Settings

DB_HOST=127.0.0.1

DB_PORT=3306

DB_USER=your_db_username

DB_PASS=your_db_password_here

DB_NAME=fsl_learn

# Python ML Microservice URL

ML_SERVICE_URL=http://127.0.0.1:8000

    Sample PHP configuration excerpt from backend/php/config.php:

    define('DB_HOST', getenv('DB_HOST') ?: '127.0.0.1');

define('DB_PORT', getenv('DB_PORT') ?: '3306');

define('DB_USER', getenv('DB_USER') ?: 'root');

define('DB_PASS', getenv('DB_PASS') ?: '');

define('DB_NAME', getenv('DB_NAME') ?: 'fsl_learn');

define('ML_SERVICE_URL', getenv('ML_SERVICE_URL') ?: 'http://127.0.0.1:8000');

    5. Set Up the Python Machine Learning Service¶

    The ML service processes hand landmark coordinates sent from the browser client during live sign recognition.

    Open a terminal or command prompt, navigate to the backend/ directory, create a Python virtual environment, and install all required packages:

    cd backend

python -m venv venv

# On Windows (PowerShell or Command Prompt):

.\venv\Scripts\activate

# On macOS or Linux:

# source venv/bin/activate

python -m pip install --upgrade pip

pip install -r requirements.txt

    The requirements.txt file installs the following packages:

    • fastapi==0.115.0

    • uvicorn[standard]==0.30.6

    • python-multipart==0.0.9

    • pydantic==2.9.2

    • numpy>=1.26.0,<2.2.0

    • scikit-learn>=1.3.0,<1.6

    • joblib>=1.3.0

    • mediapipe>=0.10.0

    • opencv-python>=4.8.0

    6. Start the Services¶

    Start the Python FastAPI server from the active virtual environment:

    python run.py

    The terminal displays startup information confirming Uvicorn is listening:

    =======================================================

 FSL Learn — ML Recognition Service

 URL: http://0.0.0.0:8000/api/recognize

 DB API:  served by PHP on Laragon Apache

=======================================================

INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)

    Confirm that HTTP 200 OK is returned with {"status":"ok"}.

    1. Verify PHP Database Connection: Navigate to the PHP backend health test URL in your browser:

    System User Guide¶

    This guide explains how to use the FSL Learn platform according to your assigned user role: Student (Learner), Teacher, or Principal.

    Every feature described below is implemented in the platform's user interface. Please follow the numbered instructions and exact button names to complete each task.

    User Roles and Permissions¶

    The system enforces strict role-based access control. Review the permissions assigned to each account type:

    | User Role | Dashboard URL | Accessible Navigation Items | Primary Responsibilities |

    | :--- | :--- | :--- | :--- |

    | Student | student.html | FSL Lessons, My Classroom, Profile | Browse lessons across Alphabet, Basic, and Intermediate levels; watch sign demonstration GIFs; mark lessons complete; take multiple-choice quizzes; track personal scores. |

    | Teacher | teacher.html | FSL Lessons, Classrooms, Sign and Spell, Profile | Create and manage classrooms; enroll new and existing students; track individual and class progress metrics; broadcast live sign demonstrations via camera recognition. |

    | Principal | teacher.html | Report, Code Generator, Profile | Generate and expire 16-character Teacher Registration Codes; review school-wide learning progress; export official Teachers, Students, and Progress reports to PDF/CSV. |

    Note

    Students can belong to only one classroom at a time. If a student transfers to a new classroom, their previous teacher must remove them before the new teacher can enroll them.

    Accessing the Platform and Logging In¶

    All users access the application through the centralized sign-in interface. Follow these steps:

    1. Open your web browser and navigate to the application login page: http://localhost/fsl_learn/frontend/login.html

    2. The login screen presents two role tabs: Student and Teacher:

      • To log in as a student, click the Student tab.

      • To log in as a teacher or principal, click the Teacher tab.

    3. Enter your assigned Username and Password.

    4. Click the Login (or Sign In) button.

    5. Upon successful authentication, students are directed to student.html, while teachers and principals are routed to teacher.html.

    Teacher Account Registration¶

    New teachers must register an account using a valid Teacher Registration Code generated by the School Principal:

    1. Navigate to the login page (login.html) and select the Teacher tab.

    2. In the registration form (or by toggling to the register view), complete the required fields:

      • First Name and Last Name (combined into Full Name)

      • Username (3 to 30 characters; letters, numbers, underscores, dots, or hyphens)

      • Email Address (optional, for contact records)

      • Password (minimum of 6 characters)

      • Confirm Password (must match password exactly)

      • Teacher Registration Code (16-character code in the format FSL-XXXXXXXX-XXXXXXXX)

    3. Click the Create Teacher Account button.

    4. The system validates the code against the database. If the code is active and unredeemed, your teacher account is created immediately and you are logged in to the Teacher Dashboard.

    Teacher Classroom Management¶

    Teachers organize their learners into distinct classrooms.

    Creating a Classroom¶

    Follow these steps to establish a new classroom:

    1. Log in to the Teacher Dashboard (teacher.html).

    2. Click Classrooms in the left sidebar navigation (data-view="students").

    3. Click the Create New Classroom button (openCreateModal()).

    4. In the modal dialog:

      • Enter the Classroom Name (e.g., Grade 1 - Daisy).

      • Enter a brief Description (optional).

    5. Click Create Classroom.

    6. The system generates a unique 6-character alphanumeric Classroom Code (e.g., QPELNG) and displays the classroom in your directory.

    Managing Classroom Details¶

    Follow these steps to update or inspect a classroom:

    1. In the Classrooms list, click on any classroom card to open its detail view.

    2. To update the name or description, click the edit icon, update the fields, and click Save Changes.

    3. To view enrolled learners, scroll down to the Classroom Learners table.

    Warning

    Deleting a classroom is irreversible. Deleting a classroom permanently disassociates its enrolled students and deletes classroom-specific quiz results. Always ensure student records are backed up before removing a classroom.

    Enrolling and Managing Learners¶

    Teachers create student accounts directly inside their classrooms. Students do not self-register on the public landing page.

    Adding a New Student to a Classroom¶

    Follow these steps to create and enroll a new student account:

    1. In the Teacher Dashboard, select Classrooms and click your desired classroom.

    2. Click the Add Learner button to launch the student creation modal.

    3. Complete the learner profile details:

      • Full Name (e.g., Marian Marchan)

      • Username (e.g., marian10949)

      • Password (temporary password for the pupil, at least 6 characters)

      • Age (e.g., 10)

      • Gender (select Boy, Girl, Male, Female, or Other)

    4. Click Save Learner.

    5. The student is created in the database, assigned the student role, and enrolled into your classroom. Provide the username and temporary password to the student or their guardian.

    Enrolling an Existing Learner¶

    Follow these steps to link a student account to your classroom:

    1. If the pupil already has an account in the system and is not currently enrolled in any other classroom, open your classroom and click Enroll Existing Learner.

    2. Select or search for the learner by username or name.

    3. Click Confirm Enrollment. If the student is already enrolled in another classroom, an alert will notify you to resolve the transfer with the previous teacher first.

    Student Learning Experience¶

    Students use the FSL Lessons portal to study Filipino Sign Language vocabulary:

    1. Log in as a student on login.html.

    2. Click FSL Lessons (data-view="learn") in the left sidebar or bottom mobile bar.

    3. The screen presents three progressive learning tiers:

      • Alphabet: 26 letters of the FSL alphabet.

      • Basic Vocabulary: 15 categories (Numbers, Colors, Fruits, Vegetables, Animals, Food, etc.).

      • Intermediate Vocabulary: 9 categories (Occupations, Transportation, Emergencies, Community, etc.).

    4. Click on a level, then select a category card (e.g., Colors or Everyday Greetings).

    5. Click on an individual lesson card to open the Lesson Viewer:

      • Observe the high-definition animated sign demonstration GIF.

      • Read the English and Filipino vocabulary term.

      • Review the descriptive signing instructions and Helpful Tips.

    6. Practice the sign with your hand.

    7. Click the Mark Lesson as Complete button. The system updates your progress bar and awards completion credit.

    Taking Module Mastery Quizzes¶

    Each learning level and category includes multiple-choice quizzes to evaluate sign comprehension:

    1. Navigate to FSL Lessons and scroll to the bottom of the module or category to find the quiz banner (e.g., Alphabet Mastery Quiz).

    2. Click Start Quiz.

    3. Read the prompt and examine the displayed sign image or question term.

    4. Click one of the multiple-choice options.

    5. The animated Feedback Tray slides up from the bottom of the screen:

      • A green tray with a checkmark indicates a Correct response.

      • A red tray indicates an Incorrect response and highlights the correct sign.

    6. Click Continue to move to the next question.

    7. Upon answering all questions, the quiz completion summary appears, displaying your total points, total questions, and percentage score.

    8. Scores meeting or exceeding 70% earn passing status and are recorded in the database under quiz_results.

    Troubleshooting and Diagnostics¶

    This guide provides solutions for common issues encountered when setting up, running, or using the FSL Learn platform.

    Follow the numbered diagnostic and repair steps in each section to resolve problems quickly.

    Note

    If you encounter an unexpected error or an issue not covered in this guide, record the exact error text, the browser console output (F12 > Console), and the server terminal logs, then contact the development team or your school IT administrator.

    Common Problems and Fixes¶

    Problem 1: Database Connection Failed (PDOException [2002])¶

    Symptom: When loading the website or submitting the login form, the application displays an error: "Database connection failed", "SQLSTATE[HY000] [2002] Connection refused", or an HTTP 500 Internal Server Error.

    Cause: The MySQL database service is stopped, running on a non-standard port, or the database credentials in backend/php/config.php do not match your MySQL server settings.

    Fix:

    1. Open the Laragon control panel (or XAMPP control panel).

    2. Check the MySQL service indicator. If it is stopped, click Start All (or Start next to MySQL).

    3. Confirm that MySQL is listening on port 3306. If MySQL is running on another port (such as 3307), update the port in backend/php/config.php or set the environment variable DB_PORT=3307.

    4. Verify that the database fsl_learn exists. Open HeidiSQL or phpMyAdmin, log in with host 127.0.0.1, user root, and empty password (or your configured root password), and verify the database is listed.

    5. Check backend/php/config.php to ensure the credentials match your server configuration:

    DB_HOST=127.0.0.1

DB_PORT=3306

DB_USER=root

DB_PASS=your_password_here

DB_NAME=fsl_learn
    1. Refresh the web application in your browser.

    Problem 2: Sign Recognition Service Offline (HTTP 8000 Connection Error)¶

    Symptom: In the Teacher Dashboard under Sign and Spell (or student practice), the webcam starts, but hand signs are never recognized or classified. The browser developer console reports: Failed to load resource: net::ERR_CONNECTION_REFUSED http://127.0.0.1:8000/api/recognize.

    Cause: The Python FastAPI ML service (backend/run.py) is not running, the Python virtual environment is not activated, or port 8000 is blocked or in use by another program.

    Fix:

    1. Open a new terminal or command prompt window.

    2. Navigate to the backend/ folder of the project:

    cd C:\Users\dexte\Documents\GitHub\FINAL-FSL\backend
    1. Activate the virtual environment:
    .\venv\Scripts\activate
    1. Start the machine learning service:
    python run.py
    1. Test the service health using curl in another terminal:
    curl -i http://127.0.0.1:8000/api/health
    1. If port 8000 is occupied by another application, identify and terminate the conflicting process:
    netstat -ano | findstr :8000
    1. Locate the PID from the rightmost column and stop it in Windows Task Manager.

    Problem 3: Invalid or Expired Teacher Registration Code¶

    Symptom: During teacher registration on login.html, the form fails with the error message: "Invalid Teacher Registration Code. Please check the code and try again." or "This Teacher Registration Code has expired. Please request a new code from the Principal."

    Cause: The entered code was mistyped, already redeemed by another teacher, or the code's expiration timestamp (expires_at) has passed.

    Fix:

    1. Verify that the registration code follows the exact format: FSL-XXXXXXXX-XXXXXXXX (16 hexadecimal characters separated by hyphens).

    2. Ensure no leading or trailing whitespace was accidentally copied.

    3. Have the School Principal log in to teacher.html using the principal credentials.

    4. In the Principal Dashboard, click Code Generator (data-view="code").

    5. Review the Teacher Registration Codes table:

      • If the code shows is_used = Yes, it has already been redeemed.

      • If the code shows Expired, its validity window has elapsed.

    6. The Principal should generate a fresh code and provide it to the teacher. Refer to the Code Generator section in the User Guide.

    Problem 4: Learner Enrollment Conflict (Single Classroom Restriction)¶

    Symptom: When a teacher attempts to add or enroll a student, the system returns an HTTP 409 Conflict error: "This learner is already enrolled in classroom 'Grade 1 - Daisy'. Each student can only belong to one classroom at a time."

    Cause: The database constraint uq_student on table classroom_members strictly prevents a student from being registered in more than one classroom concurrently.

    Fix:

    1. Identify the student's current classroom by consulting the previous teacher or asking the Principal to review the Students Report (data-view="report").

    2. Have the previous teacher open their classroom in teacher.html, locate the learner in the roster, and remove the student from that classroom.

    3. Once unassigned, the new teacher can immediately enroll the learner using the Enroll Existing Learner option.

    Problem 5: Webcam Feed Is Black or Camera Access Denied¶

    Symptom: When opening Sign and Spell, the camera box remains completely black, or a browser pop-up displays NotAllowedError: Permission denied.

    Cause: The browser blocked webcam access, camera permissions were dismissed, or another video conferencing application (Zoom, Microsoft Teams, Google Meet) has locked the webcam hardware.

    Fix:

    1. In Google Chrome or Microsoft Edge, look at the URL address bar. Click the Camera Settings icon on the left side of the address bar.

    2. Change the camera permission from Block to Allow.

    3. Close any external applications that might be using your webcam (e.g., Zoom, OBS, Teams).

    4. Refresh the webpage (F5 or Ctrl+F5).

    5. Ensure the room has adequate front-facing lighting so MediaPipe can detect hand landmarks accurately against your background.

    Problem 6: API Requests Return HTTP 404 Not Found (Apache mod_rewrite)¶

    Symptom: Frontend network requests to /fsl_learn/api/auth/login or /fsl_learn/api/classrooms fail with HTTP 404 Not Found.

    Cause: Apache's mod_rewrite module is disabled, or the .htaccess file was not copied into the web root directory during file deployment.

    Fix:

    1. Verify that the .htaccess file exists in C:\laragon\www\fsl_learn\.htaccess. If missing, copy it from backend/php/.htaccess:
